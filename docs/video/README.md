# Companion video: script, demos and checks

A plan for a YouTube video about this project: *"I tested CAG against RAG on my laptop. The trick mattered less than the model."*
It follows the format of the helpdesk-rag video (`../helpdesk-rag/docs/video/`): a segment plan, narration written to be read aloud, animated clips
and terminal clips, and a recording guide. This folder is optional; the project does not depend on it.

## Status

| Piece | State |
|---|---|
| `script.md`: 12 segments, narration (about 950 words, about 7.5 minutes), visuals, data appendix, upload text | done |
| `demo/`: the scripts whose output the terminal segments show, plus captured output in `demo/captured/` and captured data in `demo/data/` | done; all run |
| `check_numbers.py`: re-computes every number in the script from the repository | done; passes |
| `recording-guide.md` (generated by `make_recording_guide.py`): setup, cue tables, honesty checks, editing notes | done; cue times are estimates |
| Narration audio (Kokoro, synthetic voice `af_heart`), `narration/build_narration.py` | built; **pronunciations not listened to** |
| Twelve clips in `anim/` (Remotion): seven animated (1, 2, 3, 5, 8, 10, 12) and five terminal replays (4, 6, 7, 9, 11) | built; frames spot-checked |
| `finalize.py` -> `upload/cag-video-draft.mp4` (about 6.6 min, 1080p), captions, chapters, tags, thumbnail, checklist | built; **draft, not uploaded** |

The helpdesk-rag video was built with Kokoro (synthetic voice), Remotion (React animations) and `finalize.py`; see `../helpdesk-rag/docs/video/README.md`. This folder reuses that pipeline
(`../helpdesk-rag/docs/video/narration/.venv` for Kokoro, and its `anim/node_modules`, linked into `anim/`). Rebuild: `narration/build_narration.py`, `anim/make_captures.py`, render the clips, then `python3 finalize.py`.
Terminal segments are labelled replays on screen, not live recordings.

## What is here

| Path | What it is |
|---|---|
| `script.md` | Segment plan, narration, visuals, on-screen captions, Appendix A (the numbers, as JSON), B (before you record), C (title, description, tags, disclosure) |
| `demo/seg4_cache.py` | Live: unloads the model, then shows the cold first call and three cached questions (about 3 minutes, needs Ollama on `CAG_OLLAMA_HOST`) |
| `demo/seg6_results.py` | Offline: the held-out results table, from `eval/baselines/` |
| `demo/seg7_quotes.py` | Offline: quoted "evidence" from the 8B model checked against the sections it cites |
| `demo/seg9_outage.py` | Offline replay of a real captured run (`demo/data/chaos-8b.json`): Ollama killed mid-request |
| `demo/seg11_gate.py` | Offline: the regression gate on a throw-away copy of the last commit |
| `demo/data/` | `chaos-8b.json` (captured outage run) and `pii-test.json` (captured redaction test) |
| `demo/captured/` | The output each demo printed when it was last run, for building replays |
| `check_numbers.py` | Verifies Appendix A and the segment times; exit code 1 on a mismatch |
| `make_recording_guide.py`, `recording-guide.md` | Generator and result for the terminal-segment guide |

## Verify before you record

```bash
PYTHONPATH=src python docs/video/check_numbers.py     # must end with ALL NUMBERS MATCH
python docs/video/make_recording_guide.py             # after any change to the narration
```

## Honesty notes (also said in the video)

- The 90 test questions were written by the AI assistant that built the project; the owner waived the independent human review (`docs/11-roadmap-status.md`).
- Everything ran on one machine, one run per setting. Treat the numbers as a comparison of setups on the same questions, not a benchmark.
- Segment 9 is a replay of captured data and must be labelled as one on screen. Segment 4 is live; its timings vary by a few seconds per run.
- The knowledge base is Ollama's documentation (MIT); the models belong to their publishers (check their licences). The helpdesk dataset used elsewhere in the project (CC-BY-NC) does not appear in this video.
- If you use a synthetic voice, use YouTube's altered/synthetic content disclosure when uploading.
